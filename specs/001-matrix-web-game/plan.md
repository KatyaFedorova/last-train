# Implementation Plan: Matrix Web Game on GitHub Pages

**Branch**: `001-matrix-web-game` (work on `main`, no branch created) | **Date**: 2026-09-25 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/001-matrix-web-game/spec.md`

## Summary

The terminal game works: 86 unit specs and all 56 acceptance scenarios pass. SwarmForge added a **server-rendered** web page, which can't be hosted on GitHub Pages and uses dropdowns instead of typed commands. This plan replaces it:

- The four core namespaces become portable `.cljc`, so the same rules run in Babashka (CLI and tests) and in the browser through **Scittle**.
- A pure `last-train.terminal` session drives a static Matrix-style page: black background, green monospace text, typed commands only.
- Four new validated puzzles are added, and the page picks one at random.
- Web acceptance steps call the pure `terminal` session functions directly, the same ones the page calls. There's no browser automation (user decision).
- A GitHub Actions workflow verifies everything, then publishes to Pages.

## Technical Context

**Language/Version**: Clojure through Babashka (bb ≥ 1.12) for the CLI and tests; ClojureScript interpreted by Scittle (pinned exact version) in the browser; the shared code is `.cljc`.

**Primary Dependencies**: Scittle (from the CDN), speclj 3.13 (existing), babashka.http-server (local serving), and the APS Babashka tools (`gherkin-parser`).

**Storage**: none. The session lives in page memory only.

**Testing**: Speclj unit specs (`bb spec`), APS Gherkin acceptance (`bb acceptance`) with web steps calling `terminal` session functions directly, and property tests (`bb property`, kept separate).

**Target Platform**: static site on GitHub Pages; current Chrome, Firefox, Safari and Edge on desktop and mobile.

**Project Type**: CLI + static web app sharing one pure core.

**Performance Goals**: playable within 5 s of opening the URL (SC-001). Scittle is about 1 MB gzipped from the CDN, and the game source is about 20 KB.

**Constraints**: no server and no API keys (FR-008, FR-013); every asset path relative, so the `/last-train/` sub-path works; AA contrast; no horizontal scroll at 360px.

**Scale/Scope**: 5 puzzles; about 6 source namespaces; 18 existing feature files plus about 3 new ones.

**Structure Decision**: a single project. The pure core is `.cljc` in `src/`, the browser shell is in `web/`, and the environment adapters are in `adapter/`. This keeps the existing `src`/`adapter` split the constitution requires.

## Phases

1. **Portable core**: rename to `.cljc` and fix `Pattern/quote`; `bb spec` and `bb acceptance` stay green. Make `bin/acceptance` work with the bb parser (FR-015, US3 partly).
2. **Terminal session + static page**: `terminal.cljc` with specs, `web/`, `adapter/site.clj`, `bin/last-train-web`. Delete the server page. Rewrite `web_steps.clj` for the browser. The existing web features pass in Chrome (US1, FR-001…006, 009…012, 016).
3. **Puzzle catalog**: name the puzzles, search for and add 4 new ones, `valid?`/`pick`, CLI `--seed`, `puzzle-catalog.feature` (FR-007…007c, SC-007).
4. **Publish**: Pages workflow, enable Pages, README (US2, FR-013/014/018, SC-006).
